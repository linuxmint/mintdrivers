# Validacao manual - 1.0 RC1

Pacote: `mainuan-gestao-drivers_1.0~rc1_all.deb`. Usar VM com snapshots;
nenhum destes comandos de instalacao/upgrade/purge foi executado pelo Codex.
O caractere ~ esta no meio do nome e foi colocado entre aspas nos comandos.
Nao adicionar PPAs, atualizar o sistema nem forcar NVIDIA/Broadcom incompativel.
Sem hardware adicional, estado vazio e correto. O RC1 nao e 1.0 final.

## Instalacao limpa

```bash
sudo apt install './mainuan-gestao-drivers_1.0~rc1_all.deb'
dpkg -s mainuan-gestao-drivers
dpkg -L mainuan-gestao-drivers
command -v mainuan-gestao-drivers
mainuan-gestao-drivers --version
mainuan-gestao-drivers --help
mainuan-gestao-drivers
```

Esperado: versao 1.0~rc1 (1.0 RC1), Architecture all, Qt6, titulo Gestao de
Drivers e launcher org.mainuan.GestaoDrivers. Loading precede resultado;
nenhum driver necessario nao e erro. Sobre e diagnostico usam a mesma versao.
Testar abrir pelo menu Plasma, icone, tema, fonte, redimensionamento e fechar.

```bash
mainuan-gestao-drivers test
mainuan-gestao-drivers --debug 2>&1 | tee mainuan-rc1-debug.log
```

Percorrer os 28 cenarios. Todos os dados e aplicacoes em test sao ficticios.
Revisar instalado/recomendado/ativo, fontes de terceiros, blockers de preflight,
MOK/reboot, Live, backend error, PackageKit indisponivel e estado vazio.
Abrir previa e confirmacao: nomes concretos de pacotes, instalar/remover,
origem, reboot/MOK; indicador Versao candidata (RC), Cancelar como default.
Em test pode aplicar simulacao; nunca usar dados ficticios em transacao real.

Tab/Shift+Tab navegam, Space seleciona, Enter aciona controle focado e Esc fecha
dialogo. Revisar com leitor de tela. Em escala 100/125/150/200% e janela pequena,
texto deve quebrar/rolar sem ocultar comandos. Nao forcar X11. Ajuda > Copiar
informacoes de diagnostico somente copia localmente; revisar antes de compartilhar.
Nao deve conter usuario, hostname, home, sysfs path, credenciais ou chaves.

## Repositorios e hardware: somente leitura

```bash
ubuntu-drivers devices
dpkg-query -W ubuntu-drivers-common
```

Se houver um pacote NVIDIA realmente detectado, consultar apenas esse nome:

```bash
apt-cache policy NOME_DO_PACOTE_REALMENTE_DETECTADO
```

Comparar Candidate/pinning/origens APT com tooltip/diagnostico e recommended UDC.
Versao instalada pode diferir da candidate; PPA mais novo nao candidato nao deve
ser escolhido pelo aplicativo. Origem third-party nao implica DKMS ou inseguranca.
Nenhum gerenciamento proprio Mesa/PPAs e oferecido. Sem driver elegivel, nao
instalar artificialmente um pacote para fingir cobertura de hardware.

## Upgrades diretos

Criar tres snapshots independentes, respectivamente com **0.4**, **0.5** e **0.6**
instalados. Para cada um, registrar antes:

```bash
dpkg -s mainuan-gestao-drivers
dpkg-query -W -f='${Conffiles}\n' mainuan-gestao-drivers
ls -l /etc/sudoers.d/
sudo apt install './mainuan-gestao-drivers_1.0~rc1_all.deb'
mainuan-gestao-drivers --version
dpkg -L mainuan-gestao-drivers
```

Verificar em todos os casos:

```bash
test ! -e /etc/sudoers.d/mainuan-gestao-drivers-gtk-legacy
test ! -L /etc/sudoers.d/mainuan-gestao-drivers-gtk-legacy
test ! -e /usr/bin/mainuan-gestao-drivers-gtk-legacy
test ! -L /usr/bin/mainuan-gestao-drivers-gtk-legacy
test ! -e /usr/lib/mainuan/mainuan-gestao-drivers/gtk_legacy.py
test ! -e /usr/lib/mainuan/mainuan-gestao-drivers/load-broadcom-modules
test ! -e /usr/share/mainuan/mainuan-gestao-drivers/gtk-legacy.ui
test ! -e /usr/share/man/man1/mainuan-gestao-drivers-gtk-legacy.1.gz
mainuan-gestao-drivers
```

Mantido rm_conffile com limite **0.5~**, comparado com a versao antiga: cobre
0.4 -> RC1 sem passar por 0.5. Em 0.5/0.6 a migracao ja deveria ter ocorrido.
Se o administrador alterou o conffile antigo, dpkg-maintscript-helper preserva
backup .dpkg-bak inativo. Validar esse caso apenas em snapshot VM; purge deve
tratar backups de migracao. Nao usar limpeza rm -f improvisada.

## Purge

Em cada snapshot de upgrade e na instalacao limpa:

```bash
sudo apt purge mainuan-gestao-drivers
test ! -e /usr/bin/mainuan-gestao-drivers
test ! -L /usr/bin/mainuan-gestao-drivers
test ! -e /usr/share/applications/org.mainuan.GestaoDrivers.desktop
test ! -e /etc/sudoers.d/mainuan-gestao-drivers-gtk-legacy
test ! -L /etc/sudoers.d/mainuan-gestao-drivers-gtk-legacy
test ! -e /etc/sudoers.d/mainuan-gestao-drivers-gtk-legacy.dpkg-bak
test ! -e /etc/sudoers.d/mainuan-gestao-drivers-gtk-legacy.dpkg-remove
test ! -e /usr/lib/mainuan/mainuan-gestao-drivers/mainuan_drivers/qt/application.py
```

Nao executar autoremove para este teste. O pacote nao deve remover PyQt6,
PackageKit, UDC/KDE explicitamente nem preferencias pessoais. Guardar logs e
estado dpkg se algum teste falhar, sem operacoes privilegiadas adicionais.

## Live, Secure Boot e ativacao

Em VM com ISO Live de teste que disponibilize o aplicativo, confirmar deteccao,
previa e modo test, mas Aplicar bloqueado. UNKNOWN tambem bloqueia; nao montar
instalacao alvo nem tentar mudar drivers fora da sessao. Registrar cmdline e
findmnt para investigacao local, sem inclui-los em relatorio publico se contiverem
identificadores desnecessarios.

Secure Boot/MOK/NVIDIA/Broadcom reais requerem hardware elegivel. Fakes nao sao
prova manual. Somente leitura: mokutil --sb-state; quando houver certificado
publico DKMS corretamente identificado, mokutil --test-key /CAMINHO/PUBLICO.der.
Nao ler chave privada, importar MOK, definir senha, modificar firmware ou carregar
modulos. Uma MOK diferente nao basta; pending/unknown continuam conforme blockers.
Pacote instalado nao prova driver ativo: conferir sysfs e o estado apos reboot
decidido manualmente pelo usuario. Nao ha reboot automatico.

## PackageKit: probes de desenvolvimento

No checkout, como usuario normal em sessao Plasma:

```bash
python3 tests/probe_packagekit_readonly.py
```

Esperado Introspect/CreateTransaction/Resolve/Package/Finished, nenhuma mutacao.
Para validar opcionalmente mutacao REAL na VM com pacote inofensivo, sem drivers:

```bash
python3 tests/manual/packagekit_mutation_probe.py full \
  2>&1 | tee -i packagekit-rc1-mutation.log
```

Confirmar manualmente INSTALAR hello, autorizar via PolicyKit, aguardar verificacao
e confirmar REMOVER hello na MESMA execucao. Nunca executar como root. Se hello
ja estiver instalado, o probe recusa; nao o remover artificialmente para passar.
Cancelar o PolicyKit em execucao separada, conforme tests/manual/README.md.
Autorizacao em cache pode nao abrir dialogo: registrar isso, nao contornar politica.
Se houver timeout, nao matar PackageKit nem repetir operacoes; verificar estado
e seguir a contingencia manual documentada. Probe nao e instalado pelo .deb.
